# 商城商品目录

这里存放「商城」栏目的商品。**每位协作者只需在本文件夹新增一个 JSON 文件即可上架商品**，不需要改动其他代码；合并后重新构建（`npm run build`）即可生效。

## 文件格式

一件商品一个文件，文件名必须是 `商品id.json`，例如 `nickname-badge.json`：

```json
{
  "id": "nickname-badge",
  "name": "专属昵称徽章",
  "description": "在留言和照片署名旁展示一枚小徽章（虚拟荣誉，兑换后联系管理员开通）。",
  "price": 60,
  "enabled": true,
  "images": [
    {
      "src": "images/nickname-badge.webp",
      "alt": "专属昵称徽章示意图"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 小写字母、数字、连字符，必须与文件名（去掉 `.json`）一致；全店唯一，上架后不要修改，否则库存重新计数 |
| `name` | 是 | 商品名，40 字以内 |
| `description` | 是 | 商品说明，200 字以内；请注明发放方式 |
| `price` | 是 | 所需积分，正整数 |
| `stock` | 否 | 库存，正整数；缺省表示不限量。兑完自动显示「已兑完」 |
| `enabled` | 否 | `false` 时下架（保留文件和兑换记录）；缺省为上架 |
| `images` | 否 | 最多 8 张商品配图；每项包含相对路径 `src` 和替代文本 `alt` |

图片文件放在 `mall-goods/images/`，`src` 从该目录相对路径填写；支持 JPG、PNG、WebP 和 AVIF。构建时会检查图片存在、路径未越界，并把图片复制到网站静态资源中。图片由静态文件提供，不存进 `mall.sql` 或兑换记录表。

## 规则

- 商品按积分从低到高展示；构建时会校验格式，不合格的文件会导致构建失败并提示具体文件。
- 价格为服务端信任数据：兑换扣分时以本目录中的 `price` 为准，前端无法改价。
- 兑换立即扣积分、不可撤销，兑换记录保存在私有数据库 `mall_redemptions` 表；发放（实体或虚拟）由维护同学按记录另行安排，请在说明里写清联系方式。
- 下调已售商品的 `stock` 到低于已兑数量时，商品会显示为已兑完，不会删除已有兑换记录。
